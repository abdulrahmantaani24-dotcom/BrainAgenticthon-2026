# Proposed integration acceptance tests

These are **proposed, not implemented or executed** acceptance tests. They do not alter or replace existing tests. The executed audit checks are reported in [the audit](task-c-audit.md#checks-actually-executed-in-the-original-audit). Raw `main-tests.xml`, `calibration-test.xml`, `task-c-collection.log`, and `source-probes.json` remain in the external evidence bundle described there. The original result was **201 main tests passed, one Task C calibration test failed, and three dependency-related collection errors**; Task C did not pass all tests. These historical checks have not been rerun for this documentation-only change.

Baselines: main `1d235147cca72b888dc2028a0e5e3eed1711d00c`; Task C `1c1c997` (`1c1c99730788a733484aa92f09057c144b37f8fb`).

Compatibility boundary: all 26 groups are retained from the audit. Where a group describes a corrected scorer, stricter input policy, new CLI, or new error envelope, that requirement applies to a **new, opt-in adapter interface**, not an edit of the existing `TaskCOutput`, upstream `classification.json`, preprocessing semantics, or legacy CLI. A changed numerical profile requires a separate owner-approved version; the initial compatibility profile preserves original output values.

Test levels: U = unit/synthetic with injected backend; G = golden tensor/logit compatibility; W = trusted-weight integration in a patched isolated environment; E = authorized independent patient-data evaluation. U tests must run without A/B models, checkpoint, GPU, medical data, or network. G fixtures must be synthetic or explicitly approved/de-identified. W/E require independent provisioning; absence must be reported as unavailable/skipped, never passed.

## Required reporting convention

Every test run must identify revision, artifact/config/policy hashes, environment/precision, intended and executed test count, passes, failures, errors, expected failures, skips, and unrun prerequisites. Store runner exit codes and current-run result files. Synthetic, mocked, real-checkpoint and independent-clinical results must be labeled separately. No zero-test or collection-only run is a readiness pass. Optional artifact-dependent jobs may skip visibly in general CI, but a release requiring real checkpoint validation remains blocked until those jobs actually execute successfully.

See [strict offline and independent calibration requirements](task-c-verification-requirements.md) for C20–C25 release evidence. All 26 groups above remain **proposed and unrun**.
